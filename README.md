# 城市排水防涝泵站运行与内涝处置管理平台

面向排水泵站台账、泵组运行、排水管网与检查井养护、水位雨量监测、内涝点处置、闸门调度与抢险队出动的一体化城市排水防涝运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `drainage-pump:entries` 这一项，或调用 `resetModule(模块)`。

## 闸门调度规则（开度口径）

闸门调度不走上一条的通用动作，业务规则集中在 `frontend/src/api/gate-dispatch.ts`，
数据除调度单本身外，还单独持久化开度口径、操作留痕与并发锁：

| 键（localStorage） | 内容 |
| --- | --- |
| `drainage-pump:gate-opening-limits` | 每道闸（闸门名称 + 所属河渠）的开度上下限与水位差观察阈值，带版本号 |
| `drainage-pump:gate-traces` | 操作留痕：登记/观察/执行/改开度/终止/作废/口径调整/口径重算 |
| `drainage-pump:gate-locks` | 同一道闸的短时互斥锁（先到先得） |

规则口径：

1. **开度上下限按「闸门名称 + 所属河渠」分别配置。** 开度落到区间外的调度单不许提交，
   退回时写清是低于下限还是高于上限、具体超/差多少个百分点。
2. **水位差超阈值先观察一轮再开。** 上下游水位差超过该闸阈值时，待调度单需先「登记观察读数」；
   已观察但最新一轮差值仍超阈值，要继续观察到回落为止。
3. **同一道闸同一时段只有一条活跃单。** 重复下发按最新一版执行，旧单自动置为「已作废」，
   并在留痕里写明被哪一版顶换（作废但留痕，不物理删除）。
4. **状态单向流转：待调度 → 执行中 → 已终止。** 终止为终态，不可再执行；终止时必须录入并存下
   当时的上、下游水位读数与开度快照（`终止上游水位/终止下游水位/终止开度/终止时间/终止人`）。
5. **开度改动全程可倒查。** 每次改开度留痕：操作人、时间、由多少改成多少、调整原因；
   记录里同时带乐观版本号 `__version`，两个人先后改同一单时，拿着旧版本提交的后到者会被挡下。
6. **同一道闸两人同时操作只认先到的一次。** 先取得该闸短时锁的操作人继续，后来者被挡下并提示
   是谁、在什么时候先操作的；锁有 TTL，异常退出不会把闸永久锁死，页面「并发锁」可查看/释放。
7. **口径调整即重算。** 保存新口径后，同一道闸处于「待调度/执行中」的单子立即按新口径重算：
   越界的挂「口径越界」告警且不得继续执行，回到区间的自动解除，重算结果写入留痕。
8. **终止结论落到内涝处置待派队清单。** 终止一张调度单会在「内涝点处置」模块生成一条
   `待处置` 记录（内涝点位取闸门与河渠，影响范围写明来源调度单与终止水位差）。

页面右上角可切换「当前操作人」，方便在同一浏览器里演示两人并发、版本冲突与留痕倒查；
留痕在闸门调度页「操作留痕（倒查）」标签下按闸门/调度单检索。
